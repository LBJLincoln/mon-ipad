                        PATHWAYS EVALUATED (3 TOTAL)
================================================================================

1. KAGGLE CLI (RECOMMENDED) ✓
   ─────────────────────────
   Status: Official, mature, stable
   Effort: LOW

   Pros:
     • Official tool (Kaggle maintained)
     • Single dependency: pip install kaggle
     • GPU acceleration (T4 free tier)
     • Works in any terminal/VM
     • Reliable status polling
     • 30 hrs/week free quota

   Cons:
     • Auto-runs after push (can't schedule separately)
     • No real-time kernel logs (final output only)
     • Status limited: queued, running, complete, failed
     • Account stability issues reported

   Recommendation: PRIMARY — Use for production


2. KAGGLE MCP SERVERS (SECONDARY)
   ──────────────────────────────
   Implementations: 54yyyu/kaggle-mcp, KrishnaPramodParupudi/kaggle-mcp-server, Composio
   Status: Stable, SOC2 compliant
   Effort: LOW-MEDIUM

   Pros:
     • Native Claude Code MCP integration
     • Good for queries/discovery
     • Declarative tool interface

   Cons:
     • Cannot start kernels (designed for read-only)
     • Extra setup/dependencies
     • Less suitable for automation loops

   Recommendation: SECONDARY — Use for queries, not kernel execution


3. KAGGLE REST API (FALLBACK)
   ─────────────────────────
   Status: Official, stable, documented
   Effort: MEDIUM

   Pros:
     • Direct control, no CLI parsing
     • Fine-grained error handling
     • JSON responses

   Cons:
     • Manual HTTP auth (Basic base64)
     • More boilerplate code
     • Slower iteration/debugging

   Recommendation: FALLBACK — Use only if CLI breaks

================================================================================
                          TROUBLESHOOTING GUIDE
================================================================================

Problem: HTTP 401 Unauthorized
  Solution: Verify ~/.kaggle/kaggle.json exists and has correct credentials
  • Check: cat ~/.kaggle/kaggle.json
  • Regenerate: https://www.kaggle.com/settings/account → Create New Token

Problem: Kernel not found
  Solution: Verify kernel slug format (must be "username/slug")
  • List your kernels: kaggle kernels list -m
  • Copy exact slug from output

Problem: Notebook not found
  Solution: Verify 'code_file' in kernel-metadata.json matches filename
  • Check metadata: cat ./kernel/kernel-metadata.json
  • Verify file exists: ls -la ./kernel/nba_gpu_v2.ipynb

Problem: GPU not allocated
  Solution: Set enable_gpu: true in metadata, check quota
  • Metadata: "enable_gpu": true
  • Check quota: https://www.kaggle.com/settings/usage

Problem: Status unknown
  Solution: Kernel may not exist or slug format wrong
  • List kernels: kaggle kernels list -m
  • Verify slug: kaggle kernels status username/kernel-slug

Problem: Output files empty
  Solution: Kernel may still be running, check status
  • Check status: kaggle kernels status username/kernel-slug
  • Wait for "complete" status before downloading

Problem: File permission denied
  Solution: Fix ~/.kaggle/kaggle.json permissions
  • Fix: chmod 600 ~/.kaggle/kaggle.json
  • Verify: ls -la ~/.kaggle/kaggle.json (should show -rw-------)

Full troubleshooting: See docs/KAGGLE_SETUP.md (section 9, 7+ scenarios)
